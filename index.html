Reference build · modelled company · public data

A company's AI, on machines it owns — not rented per seat.

The corporate model rents AI per seat and per token from a vendor's cloud: the prompts leave the building, the vendor becomes a processor, and the bill grows with headcount. This build tests the other way — a modelled bank's everyday AI work (answering customers, screening inbound messages, the staff helpdesk) done by small open models in the browser on the laptops it already owns, passed node to node over WebRTC, with no server in the middle and a signed receipt for every step. The test was fixed before it ran; the result, good and bad, is below — and so is what the law says about each stack.

STEP 1 · THE COMPANY

A modelled digital bank, three departments, public data.

Each department's AI job is fed by a public labelled dataset, so every answer can be checked against a label someone else wrote. 100 items per department were held out with a published seed; the examples the models see come from the training data and never overlap the held-out items.

STEP 2 · THE LAPTOPS AND THE MESH

Every node is a browser. Every link is peer to peer.

A node is a browser tab running a model on the machine's own GPU through WebGPU. The desk hands out work and keeps the ledger; it runs no model. Nodes join by pasting two short codes (a WebRTC offer and answer) — there is no signalling server. A message for a node that is not directly linked is relayed through the peers that are, the way meshos does it.

Machines: the run below used ONE laptop. Each node is a separate Chrome process with its own profile and its own model copy, talking over real WebRTC data channels on that machine.

STEP 3 · THE LINE

Route → intent → reply, with a gate before anything leaves.

Customer support runs as a three-station line. Each station is the same small model with a different job-specific prompt: a router picks one of seven teams, the team's intent station picks the exact topic (or says "not my team" and stops the line), and the reply station drafts an answer that must cite the topic's help article. A deterministic gate then checks the draft: the right article, and no other codes, numbers, links or emails. Anything that fails is caught and goes to a person — it is not sent.

Every hop writes a receipt: which node (its Ed25519 key), which model, a hash of what it was given, what it answered, tokens, time, and the hash of the hop before. The next station checks the whole chain and every signature before it adds to it.

Three ways to do the same support work, on the same 100 items: a chain (each station on its own laptop), a pool (each laptop runs the whole line on its own share), and a one-model baseline (the largest model the laptop holds, answering in one prompt). STEP 8 · RUN IT YOURSELF

Make this browser a node.

Load a model onto this machine's GPU, then link to another node by swapping two codes. On another laptop, open this page and do the same. WHAT THIS SHOWS, AND WHAT IT DOESN'T

  
Limits, stated plainly.

  
    
    
  • One laptop. The nodes are separate browser processes on one machine, so they share one GPU. Spreading them over several laptops would add throughput; this run does not measure that.
    • 
    
  • Small models, narrow jobs. 1.5B and 3B models on classification and short templated replies. Open-ended work is out of scope here.
    • 
    
  • Licences. The station model (Qwen2.5-1.5B-Instruct) is Apache 2.0. The 3B model is used only as the comparison baseline; its licence is research-only, so a company would not run it in production as-is.
    • 
    
  • Prompts were written on a development set. Separate items from the training side of each dataset, never the held-out ones; what changed and why is logged above, committed before the measured run.
    • 
    
  • Grading is by label. Deterministic, against the datasets' own labels. The reply gate checks citation and invented figures, not tone.
    • 
    
  • Cost is electricity only. The laptops, their wear and the time to set a node up are not costed. The wattage is an estimate.
    • 
    
  • Downloads. The page, the WebLLM library and the model weights are fetched once from public hosts (GitHub Pages, jsDelivr, Hugging Face). After that the work runs locally.
